     Context

     Starting a riichi mahjong game from scratch in an empty directory
     (/Users/nya/foo). This first stage covers only the wall, dealing, and the
     draw→discard turn cycle. No action validation: no calls (chi/pon/kan/ron),
     no riichi, no win detection, no scoring. Tiles show as plaintext inside

     Files

     - index.html: layout with 4 seat areas (the human seat at the bottom, the
       others at left/top/right), a center info panel (round wind, dealer, tiles
       left in the wall, whose turn), a discard pond per seat, and a "New Hand"
       button.
     - style.css: tile box styling (fixed size, border, rounded corners, suit
       colors: man red, pin blue, sou green, honors black), plus a highlight for
       the drawn tile and a grid-wrapped discard pond (6 per row).
     - game.js: the game state and turn logic, with no DOM access.
     - ui.js: rendering and event wiring. Loaded as ES modules (<script 
       type="module">).

     Data model (game.js)

     - Tile: { id: 0..135, suit: 'm'|'p'|'s'|'z', rank: 1..9 (honors 1..7 = E S 
       W N Wh G R), red: bool }. The 136 tiles are 4 copies of 34 kinds, and one
       of each 5m/5p/5s is red (0m style label, shown in red).
     - tileLabel(tile): the one place that turns a tile into text. It becomes
       the SVG hook later.
     - createWall() builds the 136 tiles and shuffles them with Fisher–Yates.
     - State:
     { wall, deadWall /*14*/, doraIndicators, players: [{ seat, hand, drawn,
     discards }],
       dealer, current, phase: 'draw'|'discard'|'ended', roundWind }
     - newHand(): shuffles, splits off 14 tiles as the dead wall and flips 1
       dora indicator. It deals in the real order: 3 rounds of 4 tiles each to
       each player, then 1 more tile each. Then the dealer draws their 14th
       tile, so play starts in the dealer's discard phase.
     - draw(state): pops from the live wall into players[current].drawn. If the
       wall is empty, sets phase='ended' (exhaustive draw).
     - discard(state, tileId): removes the tile from the hand or the drawn slot,
       merges drawn into the hand, sorts the hand, pushes the tile onto
       discards, and moves current = (current+1)%4 with phase='draw'.
     - sortHand: orders tiles by suit (m, p, s, z), then rank.

     Turn processing (ui.js)

     - One step() loop: in the draw phase, it calls draw() automatically, then
       re-renders.
     - The human seat (seat 0, dealer/East to start) discards by clicking a tile
       in their hand, including the drawn tile, which is shown slightly
       separated on the right.
     - Seats 1–3 are simple bots: after a delay of about 400 ms they discard
       their drawn tile (tsumogiri). I chose this default because the seat
       question went unanswered. Switching to hot-seat only means dropping the
       bot branch and making every hand clickable.
     - Opponent hands render face-down (blank boxes). A "show all hands" debug
       checkbox reveals them.
     - When the hand ends, the info panel shows "Exhaustive draw" and the "New
       Hand" button restarts. No dealer rotation yet.

❯ What does the 0 tile mean- red five?                                          

⏺ Yes, 0 means a red five. 0m, 0p and 0s are the red 5-man, 5-pin and 5-sou.

  This is the standard shorthand in riichi notation, used by Tenhou and most
  hand calculators. A red five is still a 5 in play; it just adds one dora when
  it's in your hand. Writing it as 0 separates it from a normal 5 in short text.

  Each suit has one red five out of its four 5s, and in the UI it also gets a
  pinkish background (.tile.red in style.css). The label comes from tileLabel()
  in game.js. If you'd rather see 5m in red, or something like 5m*, it's a
  one-line change there, and the SVG tiles will replace it later anyway.

❯ was there a build involved in the dev process?                                

⏺ No, there's no build step. The browser runs the files exactly as written:

  - index.html, style.css and ui.js are plain HTML, CSS and JavaScript. ui.js
    loads game.js using the browser's built-in import, so there's no bundler,
    transpiler or TypeScript.
  - server.js runs directly with node server.js (which is all npm start does).
    "type": "module" in package.json just tells Node to use the same import
    syntax.
  - npm install isn't a build either. It only downloaded the ws package, which
    the server uses for WebSockets.

  When you edit a file:
  - For the front end (index.html, style.css, ui.js), reload the browser tab.
  - For server.js or game.js, restart the server (Ctrl+C, then npm start), since
    the server loaded them at startup. Restarting also resets the current game.

  If you'd like the server to restart automatically when files change, Node has
  a built-in option, node --watch server.js, which still needs no build tools.

     │                                                                         │
     │ Algorithm                                                               │
     │                                                                         │
     │ A 13-tile hand is tenpai if adding some tile kind makes a complete      │
     │ 14-tile hand. The tiles that do this are its waits.                     │
     │                                                                         │
     │ 1. Counts array: map each tile to an index 0–33 (m1–9 = 0–8, p = 9–17,  │
     │    s = 18–26, z = 27–33). A red five counts as a normal 5. The hand     │
     │    becomes counts[34].                                                  │
     │ 2. Try every wait: for each kind k (0–33), do counts[k]++. If           │
     │    isComplete(counts), k is a wait. Then undo with counts[k]--.         │
     │    - Skip k if the player already holds all 4 copies of it, because a   │
     │      wait on your own 4th tile isn't valid tenpai under standard rules. │
     │ 3. isComplete(counts): true if any of these three shapes matches.       │
     │    - Standard, 4 sets + 1 pair: for each k with counts[k] >= 2, remove  │
     │      it as the pair and call canFormSets(counts).                       │
     │    - Chiitoitsu (seven pairs): exactly 7 kinds with count 2. Four of a  │
     │      kind doesn't count as 2 pairs.                                     │
     │    - Kokushi (thirteen orphans): all 13 terminal and honor kinds        │
     │      present, with one of them doubled.                                 │
     │ 4. canFormSets(counts) (recursive): find the lowest index i with        │
     │    counts[i] > 0. If there is none, return true.                        │
     │    - If counts[i] >= 3, remove a triplet and recurse, then restore it.  │
     │    - If i is a number tile with rank ≤ 7 and counts[i+1] and            │
     │      counts[i+2] are both at least 1, remove a sequence and recurse,    │
     │      then restore it. Honors can't form sequences.                      │
     │    - Otherwise return false.                                            │
     │                                                                         │
